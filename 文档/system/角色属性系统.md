# 角色属性系统

属性展示目录由 `CharacterStatCatalog.Default` 持有共享引用，说明和属性面板读取同一目录。地图反复切换时不在每个被动说明中重复短暂加载根资源，确保 C# 目录及其导出数组的生命周期覆盖使用者。

基础成长由 `CharacterProgression` 推导；角色存档拥有学习记录、装备实例和永久加成。`CharacterStatCalculator` 重新汇总基础、永久、技能目录中已学被动及装备/宝石；不保存派生结果，不按具体技能ID处理被动。

角色选择从技能登记资源读取角色名、介绍和战斗场景。当前存档的角色由显式当前角色ID决定，不固定选悟空。未登记角色不回退到别的角色。

`Player` 持有当前血蓝与汇总属性，每秒按回血回蓝数值恢复并限制在上限；升级先刷新新上限再补满。背包读取同一计算器。技能等级变化只改变学习记录，因此刷新多次不会重复叠加。

更完整的成长资源化、Buff与其他角色迁移不在本次范围。现有装备、物品、事件、存档系统的详细设计已整理到本目录，见[系统索引](README.md)。角色基础成长仍由 `CharacterProgression` 的现有数值表提供；本次目录注册覆盖角色选择、战斗场景与技能，不声称所有角色数值已资源化。

## 属性面板注册与悬停说明

`CharacterStats` 明确声明支持的数值字段；`CharacterStatCalculator` 负责按来源汇总。`CharacterStatRegistry` 仅登记展示元数据：稳定 ID、名称、取值函数、格式函数和说明，不持有角色状态，也不参与战斗计算。默认条目由策划资源目录生成；C# 注册接口保留给运行时展示扩展。

`CharacterStatsPresenter` 将注册条目映射到旧场景的十个展示槽，按注册顺序自动分页。同 ID 注册替换原条目；移除条目后页码收敛到有效范围。名称与数值各自接收悬停，读取同一条目的说明；翻页和替换时同步更新，空槽清空说明。使用 Godot Control 原生提示，不为每个属性编写信号和页码分支。

说明来源为旧工程 `Script/BackPack/BackPack.gd` 的属性悬停函数。迁移玩法含义；闪避说明省去旧版“霸体效果”的承诺，因为当前命中结算保证的是伤害被闪避。旧版文案与当前实现不一致时，以当前玩法为准。

扩展展示项：在默认注册表登记取值、名称、格式和说明即可，面板不增加具体属性判断。扩展实际属性：同时添加数据字段、来源加成、汇总、有限数值校验及消费公式；展示注册不等于玩法接入。错误 ID 或空取值函数由注册入口拒绝；空说明允许用于外部自定义条目。

验证：编译工程；核对十八项说明非空，分页后的说明与名称一致，替换及移除不会遗留说明；沿用已有三页注册测试。

## 极速与属性资源注册

用户确定名称为“极速”，`HasteRating` 保存数值，面板显示数值及冷却缩减。公式为 `实际冷却 = 基础冷却 / (1 + max(0, 极速) / 100)`；100极速使冷却减半，不影响移速或动作速度。施放时固定本次总时长，HUD读取同一快照。

展示注册改为 `CharacterStatCatalog` 显式引用 `CharacterStatDefinition` 资源，统一放在 `Content/GameData/Stats/Registry.tres`：稳定ID、名称/说明翻译键、对应字段及格式。UI不硬写默认属性条目。字段用明确枚举集中映射，支持新字段时更新数据与映射；展示顺序和文案仅编辑资源。目录拒绝重复ID、缺失说明及非法格式。

`SkillLevelBonus` 为全技能生效等级加成，作用于已学技能且限制到上限，不解锁未学技能。极速和技能等级加成都接入基础、永久、装备、宝石和有限数值校验；被动不提供技能等级加成以避免循环。详情见技能成长系统。

所有来源先相加，再由独立冷却公式换算最终秒数。基础、永久、装备、宝石及资源化被动提供加成，计算器只汇总。

旧版依据：`Script/Base/BaseHero.gd` 在物理帧中将技能 ID 对应的 `Role1SkillInter` 每帧减 0.1；各角色施放函数写入固定数值，释放前检查其不大于 0。默认 60 个物理帧每秒时每秒减少 6，旧值并非秒数。`Scene/OtherScene/SkillIcon.gd` 将旧值除以 6 后启动自己的 Timer 显示剩余秒数。法宝则由 `BaseMagicWeapon` 及各法宝脚本使用 `SkillCD` Timer。该路径未发现通用极速或减冷却属性；新系统保留玩法数值依据，统一以实际秒数计时，不搬运按帧递减或 UI 独立计时结构。

调用链：角色属性刷新 → 汇总冷却属性 → `Player.TryUseSkill` 施放成功 → 根据技能基础冷却和当前属性计算本次冷却 → 玩家保存剩余时间。施放时固定本次总时长；更换装备不追溯修改已开始的冷却。HUD 阴影读取本次总时长，不能继续使用技能资源的原始冷却作为分母。减冷却不影响蓝耗、施放动画、普攻或怪物攻击间隔。

验证应覆盖零加成、多个来源叠加、边界限制、施放失败不启动冷却、暂停停止计时、换装不改变已有计时，以及 HUD 总时长和实际计时一致。增加字段时同步更新存档有限数值校验，不引入旧存档迁移层。

装备悬停同样读取属性目录，按非零加成生成条目，不再单独硬写十六个取值分支。添加新的展示资源后，人物面板与装备说明一起读取；新增玩法字段仍需明确实现汇总和消费逻辑。
