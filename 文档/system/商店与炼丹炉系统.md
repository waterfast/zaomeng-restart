# 商店与炼丹炉系统

## 目标与范围

迁入旧工程 SHOP、Shop_item、ldl 及炼丹炉子页的场景布局和真实引用资源，移除旧 GDScript。商店目前只出售四级强化石；炼丹炉仅提供背包浏览和强化、合成、镶嵌、幻化、分解、打造页面切换，所有加工操作均未实现，不扣钱、不修改物品。

## 模块、数据与调用链

- `GameData/Shop/Registry.tres` 显式登记商品资源；`ShopOffer` 引用物品定义、货币类型与单价。灵魂定价依照旧 `Script/Shop/SHOP.gd`：4000、10000、27000、60000。显示名称、说明和图标仍来自物品目录。
- `ShopService` 持有目录、共用背包及钱包，验证商品、数量和余额后购买。一次购买全部入包；失败不扣款，不复制旧版丢失超额物品的行为。背包沿用当前按需扩容规则。
- `LegacyShopPanel` 负责分类、搜索、分页、数量输入和购买反馈，不判断具体物品 ID。复用背包 `Box_1` 场景及 `LegacyBrowseSlot` 显示绑定，按钮背景透明，原物品图保持原样。
- `LegacyBrowseInventory` 绑定炼丹炉内旧 `Main_Backpack` 的分类、分页与格子，使用 `InventoryViewAdapter` 和共用物品说明框；不接装备、出售、合成或强化操作。
- `LegacyAlchemyPanel` 管理旧子页互斥显示、选中状态、余额及关闭；子页操作按钮禁用，显示未开放提示。打开时刷新余额，关闭时隐藏说明框。
- `WorldMapDefinition` 配置商店及炼丹炉入口，`WorldMap` 创建面板并交给 `MenuManager` 管理互斥、暂停和 Esc 关闭。

钱包归 `GameSaveData.Wallet`，已有 `Souls` 与 `Coupons` 两个 long 字段；存档序列化、非负校验、编辑器点券编辑沿用现有实现。新存档点券默认零，不添加充值或赠送规则。购买成功调用 `GameSession.Save`，保存失败明确提示玩家，不将已完成的购买误报为失败并诱导重复购买。商店底部右侧统一余额区以两行显示灵魂和点券，使用相同字体、字号与描边；场景定义布局，打开面板和购买后由绑定层刷新数值，长余额缩小字号以完整显示。

## 注册与扩展

新增商品需在物品目录登记其物品资源，并创建 `ShopOffer` 加入商店 Registry；禁止在 UI 增加物品 ID 分支。地图通过两个入口 NodePath 接入页面。加工业务需另行设计配方、消耗及装备实例规则，本次不保留旧脚本的临时数据接口。

## 失败处理与验证

校验无效或重复商品、目录外引用、非法价格及货币；拒绝非法数量、余额不足和数量上限，不改变钱物。测试覆盖四档定价、批量购买、余额不足、点券交易及存档往返、背包同步、分类分页、全部功能切换、关闭和地图入口。检查搬运资源路径及运行时场景加载。

已通过 `dotnet build`、`Tests/SaveLogic` 与 `Tests/ShopAlchemySmokeTest.tscn`。后者使用内存会话验证三张地图入口，不写玩家存档；`-- --capture` 可记录商店与六个加工页截图。缺失的炼丹炉原图按 `.import` 引用从旧缓存恢复，恢复清单位于 `Tools/shop_alchemy_textures.json`。
