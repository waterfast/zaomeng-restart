# 关卡选择与配置系统

## 目标与范围

地图入口可以对应多个关卡变体。选择面板复用同级 `zmbh-rebuild/Scene/OtherScene/LevelInfo.tscn` 的布局和对应美术（当前机器上没有 AGENTS.md 所述的原始旧工程），左侧切换变体，展示怪物、Boss、可能掉落、难度及出怪速度。关卡启动、地图画面、战斗内容和结算名称读取同一份关卡定义。当前只为花果山和魔化花果山提供可玩的变体；水帘洞、桃花源沿用现有游走刷怪模式。

## 数据与职责

`LevelDefinition` 是显式注册的策划资源，包含 ID、展示信息、进度编号、关卡容器场景、地图场景、怪物展示、普通和 Boss 掉落，以及可选的 `WaveEncounterDefinition`。`WorldMapDefinition` 的入口列表把地图按钮与可选关卡资源关联，面板只消费数据，不判断关卡 ID。出怪速度是一次挑战的运行选择，不写入资源或存档。

`WorldMap` 检查进度并打开面板；确认挑战时设置 `GameSession.SelectedLevel` 并进入关卡容器。`GameplayLevel` 在进入场景时读取选中定义，替换容器中的地图节点；单独创建怪物池和出怪控制器。带波次配置的关卡由 `ForestEncounter` 管出怪、清场、门禁与镜头边界；没有波次配置的关卡继续使用游走刷怪。关卡总控仍处理玩家、HUD、奖励、结算和存档。地图场景负责地形与表现，波次控制器用清波事件解除门禁；今后非波次地图可接不同的遭遇控制器，不必让地形资源承担刷怪规则。

## 扩展与失败处理

增加变体需建立资源并挂在入口配置；关卡容器与地图都必须存在。变体共用原关卡进度编号，因此通关仍解锁下一地图入口，不新增存档格式。魔化花果山当前复用花果山地形和猩猩 Boss，改用更密的妖猴组合、不同普通掉落及不同难度；没有单独的魔化美术和怪物资源，不在 UI 中假称已经具备。

进入前校验资源、地图和关卡场景，失败时留在选择面板并给出提示。奖励资源 ID 必须在物品目录中存在；显示“可能掉落”不保证每项在一次通关内获得。后续可将游走刷怪和奖励结算进一步拆成独立控制器，但当前只拆真实需要复用的边界。

## 验证

最小验证：编译资源类型；加载人间地图并切换花果山两项，确认标题、怪物及掉落变化；挑战进入对应定义并确认地图和波次读取配置；失败重试保持变体。完整跨关卡测试等待单独指令。
