# 碰撞墙与波次配置说明

## 先分清三件事

地形碰撞决定角色能站在哪里、能否跳过台阶。空气墙限制当前波次能走多远。镜头边界只限制画面移动。它们分别配置，调整一项不会自动调整另外两项。

| 用途 | 调整位置 | 运行时负责人 |
| --- | --- | --- |
| 平地、高台、左边界 | 地图场景的 `wall` 下各个 CollisionShape2D | Godot 物理碰撞 |
| 悬空平台 | 地图的 `stage/Platform/Shape`，保留单向碰撞 | Godot 物理碰撞 |
| 波次右侧空气墙 | 关卡资源的 `WaveEncounter/Waves` 中的 GateX | WaveEncounter |
| 开始下一波的横坐标 | 同一波资源的 EntranceX | WaveEncounter |
| 镜头最右位置 | 同一波资源的 CameraRight | GameplayLevel |
| 通关光圈 | 关卡资源的 ExitPosition | GameplayLevel / LevelExit |

地形图片和 TileMap 不会自动生成这里的地面碰撞。图片上看起来有地砖，也必须有对应碰撞体；反过来，碰撞体伸出图片，就会出现踩空气或撞到看不见的台阶。

## 手工调整 map3 的矩形地形

打开 `Scenes/Maps/Human/Map_3.tscn`。`wall` 下的 `floor` 是整段平地，`w_wall` 至 `w_wall5` 是五块高台，`LeftBoundary` 是左边界。每块形状都是独立 RectangleShape2D，可选中对应节点调整 Position 和 Shape 的 Size；没有从高台向两边铺开的人工坡道。

矩形 Position 是中心，Size 是宽高。场景中 `wall` 的 Y 偏移为 112，因此没有旋转和缩放时：

```text
世界左边 = 节点 Position.X - Size.X / 2
世界右边 = 节点 Position.X + Size.X / 2
世界顶面 = 112 + 节点 Position.Y - Size.Y / 2
```

例如 `w_wall` 的 Position 为 `(1406.5, 335.5)`，Size 为 `(417, 161)`，左右边是 1198、1615，顶面是世界 Y=367。Godot 的 Y 越小，位置越高。

| 节点 | 左边 X | 右边 X | 世界顶面 Y |
| --- | ---: | ---: | ---: |
| floor | -15 | 5506 | 515 |
| w_wall | 1198 | 1615 | 367 |
| w_wall2 | 2303.5 | 2749 | 366.5 |
| w_wall3 | 2528 | 2750 | 223 |
| w_wall4 | 3568 | 3711 | 133 |
| w_wall5 | 3713 | 3857 | 322.25 |

以上位置/宽高来自旧 `Scene/Level/Level_3.tscn` 的真实矩形资源。运行时截图已核对地砖与碰撞边界。不要缩放整张地图或只移动地砖图层来调单个台阶；直接调整对应碰撞和相关美术位置。

最后一根高柱从平地算约382像素高，当前悟空不能从柱脚直接二段跳登顶。原 `stage` 悬空平台位于 X=3158，顶面约Y=238，路线需要先二段跳上平台，再向右跳到高柱上。如果希望路线更宽松，可以手工调整平台位置或高柱高度，同时对齐美术；不要用看不见的长坡强行铺平路线。

运行游戏后，可在 Godot 的“调试 → 可见碰撞形状”查看碰撞。运行时动态生成的空气墙在“远程”场景树的关卡根节点 `WaveGates` 下；它们不会作为节点保存在 Map_3 场景中。

## 空气墙什么时候阻挡、什么时候放行

进入关卡时，WaveEncounter 为所有 `GateX > 0` 的波次创建矩形空气墙。每面墙宽14、高800，中心为 `(GateX, 200)`，实际横向边界是 `GateX ± 7`；角色还有自身胶囊宽度，贴墙时脚点不会正好等于 GateX。`GateX <= 0` 表示该波不新建墙。

从第1波开始按列表顺序运行，不同时启动多波：

1. 角色 X 小于当前波 EntranceX 时，等待角色走入该段。
2. 角色 X 达到 EntranceX 后开始按 Monsters 队列刷怪；SpawnInterval 控制间隔，LivingLimit 控制同时存活数量，挑战面板的出怪速度缩短间隔。
3. 清波必须同时满足“队列已全部生成”和“存活怪物数为0”。Boss死亡不必然等于清波，仍有小怪/召唤物时要先清掉。死后奖励结算与尸体回收由遭遇管理。
4. 如果还存在下一波，且当前波 ReleaseGateOnClear 为 true，关闭**当前波自己的墙**，切到下一波。此时仍要走到下一波 EntranceX，下一波才开始。
5. 如果 ReleaseGateOnClear 为 false，当前墙继续存在。常用于同一场地先清小怪，再出Boss；后面的Boss波应配置在这面墙左侧，通常 GateX=0。
6. 最后一波清完时，当前实现直接标记全关清场并通知关卡，**不会关闭最后一波的墙**，即使其 ReleaseGateOnClear 为 true。它保留为关卡右边界，出口应放在墙左侧。

GO 图标表示“上一波已清、下一波尚未进入”，不代表当前已有怪物。旧项目的 `stop1` 等脚本门禁不接入新地图；当前放行全部由 WaveEncounter 和上述资源控制。

### 当前桃花源例子

配置在 `Content/Levels/peach_garden.tres` 的 WaveEncounter 中：

| 波次 | 开始 X | 出怪 X 范围 | 墙中心 X | 镜头右边界 | 清波后的行为 |
| --- | ---: | --- | ---: | ---: | --- |
| 1 | 0 | 450–900 | 1090 | 1123 | 关闭1090墙，走到1100开始第2波 |
| 2 | 1100 | 1200–1800 | 2230 | 2263 | 关闭2230墙，走到2240开始第3波 |

CameraRight 是镜头画面最右位置，不是人物能走到的位置；当前配置比 GateX 多33像素，给贴墙角色及武器留画面空间。镜头不会阻止角色移动。

## 出口允许逻辑

正常战斗关卡全部波次清完后，GameplayLevel 等待2秒，再按 ExitPosition 的 X 寻找地面，创建光圈。地面探测范围为配置 Y 上下各160像素，最终光圈脚点贴到实际碰撞顶面。桃花源配置 `(4180, 515)`，位于最后一面墙4310左侧，保留拾取和转身空间。

光圈出现不直接结算。玩家需存活、处于可输入状态、游戏未暂停，且脚点距光圈不超过85像素，再按 W 才触发胜利结算。地图试玩关没有波次，靠近配置出口后创建光圈。结算开始后关闭战斗输入；推进主线与否由关卡 AdvancesCampaign 决定。

界面保留原光圈与GO图标，已去掉额外的关卡名、波次、Buff“装备”/秒数和光圈交互白字；HP、MP、EXP数值仍属于角色框。

## 调配置时容易卡住的地方

| 现象 | 优先检查 |
| --- | --- |
| 美术是平地，角色却撞墙或踩空气 | wall 下矩形左右边/顶面是否对齐地砖；不是先改波次 |
| 小怪清完了，仍不能向右走 | 队列是否还有待生成怪物、召唤物是否活着、当前波 ReleaseGateOnClear 是否为 false |
| 出现GO但没有下一波 | 下一波 EntranceX 是否在保留墙右侧，或被高台挡住 |
| 一直等不到最后几只怪物 | SpawnRange 下方是否有地面、射线是否覆盖该高度、生成位置是否离玩家太近 |
| 高台上不刷怪 | SpawnRayTop 必须高于高台顶面（Y更小）；当前默认200无法从上方命中Y=133的柱顶 |
| 看到出口却走不到 | ExitPosition 是否位于最后墙左侧；地图地形和平台路线是否可达 |
| 调了墙，画面还是裁掉人物 | 同时核对 CameraRight；它不会随 GateX 自动更新 |
| 出口报“下方没有可站立地面” | 出口 X 是否有矩形地面，顶面是否落在 ExitPosition.Y±160 范围内 |

常规段落建议从左到右排列 EntranceX、SpawnRange、GateX；下一段 EntranceX 应在上一面墙清波放行后可达。保留墙的场内续波是例外，下一波 EntranceX 与刷怪位置都要在保留墙内。现有资源校验检查数量、概率、区间等基本合法性，不自动证明路线和地形可达。

## 验证范围

地形改动需核对矩形边界，并使用实际角色走路、单跳/二段跳、平台着陆和反向移动；波次改动需核对“待生成/存活归零 → 放行 → 跨EntranceX → 下一波 → 最终墙保留 → W出口”。HumanCampaignSmokeTest 支持 `--map-three-only`，使用真实物理移动及平台路线，通过高伤害清场隔离门禁验证，不传送玩家，不写玩家存档；它不证明低等级无作弊战斗平衡。
