# 技能系统设计

`SkillDefinition.DisplayName` 是可选的策划显示名，演示工具直接读取资源，不根据具体技能 ID 拼接名称；未填写时显示动画名称。Boss 随身光效与多段命中巡检详见怪物系统。

## 目标与本次范围

先用资源明确登记角色和技能，再由同一套学习、装配、属性计算、战斗与界面逻辑消费。移除悟空静态技能数组和特殊技能 ID 分支，不兼容旧过渡结构。

悟空登记现有9个主动、嗜血，以及旧版狂暴、永恒、辉煌。三个通用被动按旧 `Passive_Skills.gd`：最高6级，加成2/3/4/5/6/7；学习价格5000/10000/15000/20000/25000/30000。狂暴增加暴击属性，永恒每秒回血，辉煌每秒回蓝，不把暴击属性冒充固定概率。

唐僧作为第二个可选试玩角色注册，九个主动技能的动作与特效已登记，另有三个通用被动。水幻影目前仅有分身表现，紧箍咒目前仅有金色光效，水魔爆自动接续预备与爆发；这些原版控制玩法、水精通及分身联动尚未完整接入，不能将全技能表现接入等同于完整玩法还原。

唐僧普攻弹体脱离镜像挂点后清除根旋转及缩放，仅在内部精灵镜像；发射与碰撞轨迹水平一致。唐僧弹体复用旧版实际帧图；原图把弹体运动画在很宽的透明画布中，迁移时只调整 AtlasTexture 的帧区域到可见边界，原图片不变。新弹体由独立节点负责移动、碰墙和每目标一次命中，避免画布内移动与节点移动重复。天降甘露引用旧治疗动画场景；旧角色死亡动画单独迁入。

共享弹体行为使用有序 `ReleaseTimes` 配置单次或连续释放，跟随角色动作时钟。`OriginPath` 可引用角色内的手部节点作为释放位置；不配置时使用镜像后的 `SpawnOffset`。随手蓄力属于角色动画表现，不在弹体行为中判断具体角色或技能。

## 模块与数据归属

- `SkillCatalogRegistry`：唯一登记资源，显式引用每个角色的 `SkillCatalog`，按角色ID查找并验证目录。
- `SkillCatalog`：角色ID、名字、介绍、头像、选择动画、战斗场景、行为保留键、技能条目；角色选择与技能系统共用这些引用。
- `SkillEntry`：技能ID、显示文本、图标、等级上限、成长资源引用；引用主动 `SkillDefinition` 或被动属性加成，两种模式互斥。
- `PassiveSkillBonus`：指定属性和逐级数值；结果重新汇总，绝不累计写入基础属性或永久加成。
- `SkillDefinition`：施放动画、成长资源引用、冷却秒数、动作位移、命中窗口、特效，另可引用一个特殊行为场景。
- `SkillBehavior`：接受 CharacterActor，每次施放创建一个独立行为实例，配置数据保存在行为场景。结束、受击、死亡和场景退出时终止，恢复临时重力等状态。

行为时间读取角色施法动画位置，不另用物理帧累计秒数，避免渲染卡顿时动画与技能释放脱节。正常动画结束时结算尚未经过的末尾时间点，然后停止；受击、重置等中断只清理，不能补发伤害或治疗。
- `SkillLearningService`：学习、扣费、槽位、改键、应用与校验。不判断悟空/唐僧，也不认识任何具体技能ID。
- `SkillCast`/`CharacterActor`：玩家和怪物共用施放计时、命中和特殊行为生命周期；`Player` 仅额外管学习资格、蓝量和玩家冷却，怪物 AI 管自己的技能选择与冷却。
- 技能面板：复用旧版视觉行模板，按目录和页签动态创建任意数量的行，不固定10行。HUD读取当前装配动作及角色目录的技能元数据。

角色存档只保存技能ID→等级、槽位ID、物理按键；资源引用、派生属性、冷却和施放实例不进存档。

## 调用链

启动/角色选择 → 登记资源校验 → 当前角色目录 → 学习服务 → 角色学习记录。

学习/装配/改键 → 应用当前目录 → 更新输入动作和玩家槽位 → 保存。

按技能槽 → 目录核对 → 蓝耗与冷却检查 → `SkillCast` + 可选行为实例 → 统一伤害结算。

属性刷新 → 基础 + 永久 + 已学被动 + 装备/宝石 → 战斗与背包读取同一结果。

## 约束和失败处理

登记时拒绝重复角色/技能ID、缺失场景、主动/被动混用、等级/费用/加成表长度错误、非法或非有限数值、定义ID不一致。进入战斗前检查目录主动动画与行为脚本；存档引用必须属于对应角色目录，主动技能才能装配，禁止跨角色装配。未知内容明确报错，不回退到悟空。图标允许缺省并显示统一黑框。

目录和行为校验临时实例化的场景尚未加入节点树，必须在 `finally` 中调用 `Free()` 释放完整原生节点树；不能只用 C# `Dispose()` 释放托管句柄。

按键使用 `skill_1`～`skill_5` 输入动作；保留移动/攻击/菜单键。特殊行为需要的按键通过目录声明保留，不在学习服务判断技能名字。

## 扩展步骤

普通主动：配置动作资源和角色动画 → 创建条目 → 加入该角色目录。

特殊主动：额外编写独立 `SkillBehavior` 子类并创建配置场景 → 在动作资源引用；不用修改玩家或学习服务。

被动：配置属性及逐级值 → 创建条目 → 加入目录；不修改属性计算器。

角色：准备玩家战斗场景 → 创建目录 → 加入登记资源；选择界面和技能面板自动读取。

## 验证方案

验证登记错误与跨角色装配拒绝；悟空三个被动的价格、等级、重复刷新不叠加、回血回蓝按实际秒数生效；唐僧选择、目录、装配、施放、保存重载与HUD；特殊行为中断恢复；原花果山波次/镜头/提示回归。测试使用临时槽位0，禁止读写玩家存档。

## 实现入口与验证结果

登记入口 `Content/Skills/Registry.tres`，角色目录为 `Wukong/Catalog.tres` 与 `Tangseng/Catalog.tres`。元数据在条目中，等级费用在其显式引用的SkillGrowth资源中，逐级加成在 `Common/kb.tres`、`yh.tres`、`hh.tres`；目录引用共享定义，但各角色学习等级独立保存。`Tools/register_skill_catalogs.py` 是本次核对旧内容后使用的一次性迁移工具，不是运行时注册器；后续以 `.tres` 为编辑入口，不能用脚本重生成覆盖策划修改。

特殊行为负责校验依赖和数值，登记校验时实例化场景只检查结构，不入树、不施放；临时原生节点在成功与失败路径都释放。通用学习、面板与属性计算器没有悟空/唐僧或具体技能 ID 分支。

已通过：工程编译（零警告、零错误）；`Tests/SkillCatalogSmokeTest.tscn`（目录错误拒绝、18次被动升级、属性刷新不叠加、实际回血回蓝、角色选择、序列化恢复、改键/HUD、弹体伤害/治疗与死亡表现、受击及重置清理）；`Tests/GameplayUpgradeSmokeTest.tscn`（悟空全部主动、地形/镜头、连击/前进提示、4波与Boss、菜单返回）；玩家资源、存档与背包逻辑测试。试玩截图保存在 `.godot/skill-checks`。

唐僧水精通、分身联动、紧箍吸附、水魔爆二次按键及完整装备外观尚未实现。成长数值仍由现有 CharacterProgression 提供，不属于本次技能目录资源化范围。

技能费用与蓝耗现已独立为 SkillGrowth 资源；主动技能开放升级，角色技能等级加成参与有效等级，规则与编辑入口见[技能成长系统](技能成长系统.md)。特殊技能行为可以提供自己的成长预览，UI 不判断技能ID。

## 局内快捷槽表现

每个槽固定保留旧版Empty.png底框，图标使用独立Icon子节点，冷却遮罩与快捷键位于上层。空槽、学习、更换、清空只改变Icon.Texture和提示，不能清除槽位底框。槽尺寸47×47，图标四边留4像素；局内HUD仍由PlayerHud统一读取当前装备技能，不保存第二份装配状态。

扩展步骤和代码调用见[内容注册与调用指南](内容注册与调用指南.md)。主动数值提示、独立冷却与延迟启动详见[技能成长系统](技能成长系统.md)。

## 怪物与玩家共享技能

行为装配、正常结束末尾结算、受击/回收/退出清理统一移至 CharacterActor。共享弹体、火眼效果和范围攻击按 combat_actors 阵营选敌，不依赖“怪物”分组或 Player 类型。MonsterSkillChoice 引用同一 SkillDefinition，可配置等级、距离和生命区间。角色借用怪物技能时，在角色目录中显式注册其动作资源并提供相应动画；无需新增角色脚本技能ID分支。现有学习/蓝耗规则仍生效，不自动赠送或解锁怪物技能。复杂召唤、状态效果与 Boss 阶段尚未实现，扩展边界见[怪物系统](怪物系统.md)。

## 本批唐僧范围技能接入设计

已补充玄冰阵（前方三个依次扩大的冰阵）与九环圣经（近身多段范围攻击）。角色动作、技能图标和特效帧引用旧场景实际资源。两项最初使用 BurstSkillBehavior；本次为保留旧版帧偏移与叠加材质，改由 SkillEffectSequenceBehavior 引用独立动画特效场景配置释放点、位置、缩放和命中时机，沿用学习/升级/装配/冷却与统一伤害，不在玩家脚本新增技能 ID 分支。无双命中获取已接入，详见无双系统；分身联动与水精通冰冻尚未接入。验证目录、学习、动画、各级蓝耗与倍率、伤害、中断及死亡清理。

## 动作音效
AttackStep.Sound 与 SkillDefinition.Sound 显式引用可选出招声音，只有实际接受动作才交给 AudioManager 播放。ActorSoundProfile 管理命中、受击和死亡声音；CombatResolver 在非闪避且伤害大于零的真实命中后触发命中声。多阶段动作由独立行为组件拥有对应声音：FireSlashBehavior 的 AirSound / LandingSound 按空中和落地阶段触发，ProjectileSkillBehavior.ReleaseSound 按弹体释放点触发。声音不参与技能结算和冷却，缺少声音不会阻断施放。详见[音频系统](音频系统.md)。

## 公共被动对施法的修改

CharacterActor 起招前调用公共 PassiveEffectRuntime，冻结 AttackParameters；普攻、角色技能及独立法宝共用。SkillBehavior 保存快照，延迟释放时不重新读取角色当前攻击。角色动画攻速统一改变动作、命中窗口和行为释放时钟，不改变技能冷却；弹体与独立范围效果消费各自的速度、范围、表现与寿命参数。完整配置与生命周期见[战斗被动效果系统](战斗被动效果系统.md)。

## 悟空、唐僧全技能表现复刻设计

本次目标是核对两位角色全部主动技能的旧场景引用、随身光效、独立特效、敌人爆炸、镜像及释放时序。旧 GDScript 不接入。悟空动作特效保留角色动画轨道；唐僧现有移动弹体保留独立弹道，脱离镜像挂点必须同时清除旋转和缩放，避免 Godot 负缩放分解留下半周旋转。

旧独立特效的帧号、偏移、颜色、材质和缩放轨道提取到独立场景，由 `AnimatedSkillEffect` 播放及清理。命中资源、时窗、位移和恢复脉冲归效果实例；来源、技能等级、被动参数及出生版本在释放时快照。效果不查询技能 ID，按阵营结算，来源死亡、隐藏、回收或退出后清理。目标火眼保持独立 `FireEyesEffect`，跟随目标脚点，三轮爆炸按旧版 25 帧/秒播放，每轮三个伤害时点；死亡和回收均终止。

`SkillEffectSequenceBehavior` 只负责按角色动作时钟释放显式配置的 `SkillEffectCue`，包括时间、偏移、镜像、缩放、随身/世界归属及持续时间。正常收招后已释放的世界效果继续；中断不补发，取消仅持续施法的随身效果。效果资源与释放序列负责登记和扩展，不向 Player 添加角色或技能 ID 分支。

唐僧缺失的水幻影、水魔爆、圣光球、沐浴回春、紧箍咒先补充原版动作及完整表现资源并通过独立行为登记。范围命中和治疗沿用当前结算；分身联动、水精通、紧箍吸附和水魔爆二次按键控制属于玩法范围，不能把视觉复刻宣称为这些玩法已完全还原。验证必须覆盖各方向、逐动作可见帧、释放点、世界效果跟随与清理、唐僧普攻弹道，以及学习/施放回归。

圣光球同时引用 Newbullet.tscn 实际使用的 sgqbullet1.png 光刃，按旧脚本每5个物理帧释放一道、30度步进。旧脚本称 Role2Bullet7，但覆盖后的 SpriteFrames 没有该名字，不能照抄这一失效引用；当前引用该场景中实际指向光刃纹理的 Role2Bullet6 帧组。圣光球主体按旧 AnimationPlayer 的1.5倍播放压缩帧时序，四秒展示全部60帧。

火魔斩空中火圈保留25帧、9帧/秒及1.4倍播放，按完整动画时长清理，而非按单次命中间隔截断。预备、下冲、落地分别保留旧镜像、位置、颜色、缩放和播放速度。场景中的固定美术校正角与弹道散射角独立相加，不能把龙王等已有弹体的固定校正角一起翻转。

本批已验证：编译零警告、零错误；HeroEffectsSmokeTest 检查18个主动技能的左右施放、原图可见像素、火眼跟随、圣光球光刃、来源回收清理、唐僧普攻镜像及水平弹道、水爆落水命中，并补充验证火眼三轮共九次命中及自然结束；SkillCatalogSmokeTest 与 MagicAndTangsengSmokeTest 通过学习、装配、序列化、HUD、治疗、打断与死亡回归。渲染截图位于 `.godot/hero-effects`，`overview.png` 为18项效果总览。测试不读取或写入玩家存档。
