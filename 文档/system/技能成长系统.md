# 技能成长系统

先设计再实现：主动和被动均可升级，装备技能默认上限1级且不进入学习记录。旧主动面板限制1级，但角色脚本已经有递增公式；新主动目录开放10级（新设定），伤害、蓝耗沿用旧公式，学习费用按初始费用每级加500。

`.tres` 是 Godot 原生策划数据，可在 Inspector 编辑。`SkillEntry` 引用独立 `SkillGrowth`（初始费用、费用增量、初始蓝耗及一次/二次增量），动作资源只描述动作和命中；不同命中段的伤害增长保留在 `HitDefinition.MultiplierPerLevel`。UI、学习与施放共用成长数据，不通过技能ID分支。角色 `SkillLevels` 保存已学等级，`SkillLevelBonus` 为全技能生效等级加成，只作用已学技能并限制到技能上限，不修改已学记录或费用。属性汇总先装备后被动，被动不能自己提供技能等级以避免循环。

UI 正文只描述效果，图标右下角的问号使用不透明浮层，悬停展示当前生效等级的蓝耗、基础/极速后冷却、全部命中配方及被动加成。未学习展示1级预览，升级和重新打开面板时重新读取成长资源。被动数值通过 ValueAtLevel 与实际属性计算共用；名称和百分比格式来自属性注册表。特殊行为通过 DescribeValues(level) 提供当前数值，不解析正文或按技能ID分支。图标从资源读取，缺失默认黑底框；技能按钮使用黑底样式，不把升级箭头当图标。装备技能定义增加图标和默认最大等级1，多技能继续数组注册。

目录验证成长资源、非负及有限参数、等级边界和计算溢出；验证升级费用、实际蓝耗/伤害、生效等级加成、上限、换装与重复刷新。状态只属于角色与玩家，成长资源不持有运行状态。

## 策划修改入口与迁移依据

- `Content/Skills/Growth/<角色>/<技能>.tres`：费用、蓝耗递增，独立资源可复用。比如升龙斩蓝耗为10 + 3×(生效等级-1) + 2×(生效等级-1)²，学习初始100，每级费用加500。
- `Content/Skills/<角色>/Catalog.tres`：登记技能、图标、等级上限、动作引用；这是注册目录，未把成长公式堆在目录里。
- `Content/Skills/<角色>/<技能>.tres`：基础冷却秒数、普通命中段的倍率与每级增量、动作时序。
- `Content/Skills/Behaviors/*.tscn`、唐僧弹体场景：特殊技能的命中资源。火魔斩分段增量0.15/0.15/0.5、火眼每跳0.15、冰龙波0.05；独立行为可提供成长预览，不让界面判断技能ID。

旧数据学习等级在伤害计算前加1，迁移按已学1级初始化对应倍率，然后每级加增量。治疗沿用旧公式的常数项0.02，先取整再加缺血增益；不误当成每级2%最大生命。旧物理帧冷却统一除6后存为秒数。目录里的主动最高10级是本次新设定，旧面板仅开放1级。

已通过 ContentSystemsSmokeTest、SkillCatalogSmokeTest 验证有效等级蓝耗、旧公式数据加载、冷却快照、主动/被动学习和真实施放。

## 冷却复核与运行职责

旧 BaseHero 每物理帧扣0.1，工程未覆盖默认60帧，旧快捷栏也除6显示秒数。烈焰闪实际写入2.8（注释中的0.8不生效），因此基础冷却为2.8/6秒。烈焰闪同时给火魔斩写入3.6/6秒关联冷却，通过动作资源显式引用目标与时长。火魔斩4.8/6秒在落地时启动：动作资源声明延迟启动，成功施放先保留时长快照并锁定技能，行为在落地调用启动；提前中断也启动以避免绕过冷却。运行状态和极速折算始终由Player负责，逐帧仅减delta，不再除6。筋斗云当前是单段飞行，旧版启动/二段升空不是当前范围，仍使用登记的0.4秒施放冷却，不宣称完全复刻两段机制。

本次复核验证：ContentSystemsSmokeTest 覆盖实际冷却递减、关联冷却、延迟锁定/中断和升级后问号数值刷新；SkillCatalogSmokeTest 在真实关卡验证火魔斩落地启动；PlayerResourcesSmokeTest 验证暂停、中断和自然恢复。渲染截图核对主动/被动问号位置与不透明浮层。
