# 物品系统设计

本设计沿用重构规划中的划分：`ItemDefinition` 描述一种物品，`Inventory` 记录角色拥有什么，后续 `Equipment` 记录穿戴关系。定义使用 Godot C# 自定义 `Resource`，保存在 `Content/Items/*.tres`；图片只留在 `Assets/Art`。游戏规则不依赖背包 UI。

## 当前数据流

`Content/Items/ItemCatalog.tres` 显式引用迁入的物品定义。TestArena 和前三关在检查器中引用目录资源，进入场景时验证 ID 唯一及堆叠上限，再从当前存档恢复背包。装备槽保存独立 EquipmentInstance，堆叠道具保存 ItemId/Count；`InventoryViewAdapter` 用目录解析名称、图标和描述，`LegacyBackpackView` 将数据填入旧版背包场景。独立的 InventoryDemo 仍使用 `InventorySample` 和 `BackpackView`。调整物品名称、图标或数值只改对应 `.tres`。

## 如意金箍棒阶段装备迁移

依据旧 `AllEquipment.gd` 的属性及旧 `LevelInfo.gd` 的早期掉落顺序，保留已有10件并补入35件，共45件武器、防具和饰品。范围包括悟空行者棍到如意金箍棒、行者服/地煞猿甲/玄武甲；唐僧松木杖/地煞权杖/白虎杖/九环禅杖与早期袈裟；八戒钉耙/胃土耙/家传金耙/诸怀耙/九齿钉耙与早期防具；沙僧月牙铲/角木铲/家传明铲/混沌铲/卷帘降魔铲与早期袍；白龙铁枪/地煞龙枪/梼杌枪/擎天华宝枪与早期甲；通用地煞灵戒/家传手镯/朱雀戒/七星守护。具体注册见目录，不包含后续地府/天庭装备或皮肤装备。

随机属性范围暂取中值，固定属性、归属、品质、售价参考原配置；不实现旧版每帧重新随机或强化。旧背包脚本通过 `Art/BackPack/AllItems/<ID>.png` 读取物品图，迁移沿用这个实际引用，缺失图从补全目录取得。说明写入翻译表；新条目尚未人工英译，英文回退旧中文文案。八戒、沙僧、白龙装备允许浏览，仍限制各自角色穿戴，对应角色运行时尚未迁入。

本次只登记内容，不为尚未设计的关卡配置掉落，也不将物品自动塞进玩家存档。可用存档编辑器添加这些装备测试。

目录引用采用显式列表，避免运行时扫描文件夹和根据 ID 拼路径。增加测试物品时，在 `Content/Items` 新建 `ItemDefinition` 资源并加入 `ItemCatalog.tres` 的 `Definitions`；两个测试场景会使用同一份内容。`ItemDefinition` 的 ID 是稳定标识，显示名称可以调整，但已有存档引用的 ID 不应随意更改。

## 场景掉落与拾取

### 容量与自动拾取调整

背包没有玩法容量限制。`InventoryService` 构造参数表示初始格子数，`Capacity` 表示当前已分配格子数；添加、卸装、拆宝石、开宝箱与任务奖励不足空格时按需扩展（至少25格）。先在副本上扩容并完成校验，再一次性提交，失败不改变格子或相关角色/货币状态。恢复快照以快照长度恢复分配大小；存档Capacity记录实际分配大小，存档编辑器新增物品后同步更新。数量仍使用int并拒绝溢出，实际规模仅受运行内存限制，不预分配百万个空槽。

背包界面仍以实际物品分页，每页25件，不展示已分配格子作为可用上限。新游戏使用25格初始分配，旧的70格不再是容量规则；存档记录的格子数也不限制后续扩容，无须存档迁移层。

`GameSettings.AutomaticPickup` 开启时，`ItemPickup` 落地满3秒自动请求领取，无需靠近；关闭时保留走近拾取。暂停、死亡与结算不能自动入包。领取失败显示“暂时无法拾取”，保留地面物品，按间隔重试；正常游戏不再以“背包满”为失败原因。

验证增加超过70件装备、跨页显示、扩容后存档往返、满初始格子卸装/拆宝石/开宝箱/任务奖励，以及非法请求和数值溢出不部分提交。

怪物死亡时由 `GameplayLevel` 对模板原表和模式额外表各判定一次，生成独立的 `ItemPickup`，不立即添加背包或保存。每件装备独立散开，堆叠物品按最大堆叠数拆分；掉落状态（定义、数量、落地和领取标记）属于场景实例，与怪物对象池无关。物品沿地形重力落地，显示图标和品质光晕。手动拾取至少显现0.6秒且落地后走近才领取；自动拾取落地满3秒领取，不占用出口的W键。

`ItemDefinition.GroundIcon` 显式引用旧 `equipment_fall.gd` 实际使用的 `Art/ItemIcon/<ID>.png`，缺失原图从 `zmbh-rebuild/assets` 补齐；未配置时使用背包图标，图标均缺失时仍显示名称。物品运行时不按ID拼路径或判断具体物品。新增物品仍在目录登记，并按需配置地面图。

已按旧ItemIcon的.import引用恢复当前登记装备的透明地面图并显式绑定GroundIcon。地面显示不再使用带棕色格子底的背包图；背包原图保持原样，不通过颜色差分删除可能与格子相近的物品颜色。验证透明角像素、地面图与背包图分别绑定，以及同屏红条和装备轮廓。

家传铃铛没有旧ItemIcon引用，改用已核对旧Magic_weapon_infor.tscn引用的透明Show_Icon/jcld.png作为GroundIcon。

拾取请求回到关卡，先检查关卡未结束和玩家存活，再调用 `InventoryService.AddItem`。成功才锁定领取、保存并播放上浮淡出；数量溢出等领取失败显示就地提示并间隔重试。入包提交后若保存失败，报告错误并保留内存物品，地面物品仍消失，避免重复领取。结算开始后停止领取；未拾取物品仅存在当前关卡，离开时清理，不自动补发或写入存档。经验与灵魂沿用玩家资源系统。

验证覆盖：死亡生成可见物品而不入包、远处等待、落地走近拾取、领取一次、用满初始格子后拾取扩容、死亡/结算拒绝领取；困难额外掉落与Boss原表均生成实物且不重复判定。

密集掉落始终显示全部图标和品质光晕；名称、数量及失败提示只显示玩家120像素内最近的一件，避免文字重叠。

## 职责边界

背包与关卡掉落共用紧凑物品说明：统一正文与属性字号、容器间距和深色底框，名称与品质使用品质色，属性和售价使用金色。说明优先出现在格子右侧，右侧空间不足时移到左侧，避免把整段文字挤成窄竖列。掉落预览不显示拥有数量。背包按参考图改为每页 5×5 格（25 件），溢出使用翻页而非一页内再纵向滚动；保留数量标签与实例宝石数据；图标使用原资源自带格子底色，不通过颜色差分删去物品上的相近颜色。验证需检查长名称、装备技能、右侧格子与掉落列表悬停。

| 模块 | 职责 |
| --- | --- |
| `ItemDefinition` | 静态 ID、分类、堆叠上限、名称、图标、描述和当前演示所需属性 |
| `ItemCatalog` | 物品定义的引用清单、按 ID 查询、基础数据校验 |
| `InventoryService` | 槽位按需扩容、增减、拆堆与合堆；操作失败不改变任何槽位 |
| `InventoryViewAdapter` | 把槽位中的 ID 和数量转成 UI 展示数据 |
| `LegacyBackpackView` / `BackpackView` | 分类、分页、选择和展示，不保存游戏状态 |

当前武器、防具、饰品和法宝均为独立、不可堆叠装备，基础攻击、暴击值与命中值来自旧 `AllEquipment.gd`。已穿戴的实例及其宝石经 `CharacterStatCalculator` 汇总到最终属性；单纯放在背包中的装备不产生加成。背包已接入穿戴、卸下和基础宝石操作，单件出售、分解和白装批量出售已接入；强化尚未实现。普通行者棍在旧版随机生成 2～6 攻击，当前静态资源保留已有的中间值 4，没有虚构随机词条。

## 后续扩展规则

装备实例已经接入：保存定义 ID、唯一实例 ID 和已镶嵌宝石，图标、名称与基础配置仍由定义提供。实例直接存在于一个背包格子或穿戴槽中，避免维护另一张易产生孤儿记录的实例表。未来随机属性应在创建时掷一次并保存，打开 UI 不重新掷值；新增强化等玩法时再增加相应字段。详见 [EquipmentInstances.md](装备实例系统.md)。

材料、消耗品仍可沿用 `ItemDefinition` 与堆叠规则；真正需要使用效果时，再引入对应行为数据和执行入口。不要把使用、穿戴、出售逻辑放进 UI，也不要把静态定义复制进每个背包槽位。

## 地面补给与增益食品
RecoveryPickupDefinition 定义拾取即恢复生命/法力的补给，ItemPickup 管理原版六秒消失，GameplayLevel 在拾取时恢复并返回成功，不加入背包。MonsterDefinition 的 RecoveryDrops 显式引用独立掉落表，旧版总概率15%，萝卜/蓝瓶/桃子权重40%/40%/20%，不受装备掉落筛选影响。ConsumableDefinition.ApplyBuff 引用 BuffDefinition，只有关卡中的当前存活角色可以使用；失败不消耗食品。食品Buff本轮只接公共接口，月老/福禄寿/月饼的数值资源待策划确定。
