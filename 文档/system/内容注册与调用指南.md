# 内容注册与调用指南

这是当前 C# 工程的操作入口。普通内容优先在 Godot Inspector 编辑 `.tres`，也可以直接编辑资源文本；只有增加新的规则或行为时才写 C#。旧项目用来核对玩法和资源，不要把旧 GDScript 接回新场景。

## 先找到内容的登记入口

| 想改什么 | 入口 | 实际消费者 |
| --- | --- | --- |
| 新增等级任务 | `Content/Quests/Registry.tres` 的 Definitions | QuestService、主地图任务面板 |
| 新增武器、防具、饰品、法宝 | `Content/Items/ItemCatalog.tres` 的 Definitions | InventoryService、EquipmentService |
| 给装备附加触发技能 | 装备的 GrantedSkills → `Content/GameData/EquipmentSkills/*.tres` | EquipmentSkillRuntime |
| 新增角色主动/被动技能 | `Content/Skills/<角色>/Catalog.tres` 的 Skills | SkillLearningService、Player |
| 新增角色目录 | `Content/Skills/Registry.tres` 的 Catalogs | 选人、学习面板、关卡装配 |
| 学习费用、蓝耗 | `Content/Skills/Growth/<角色>/<技能>.tres` | 学习、施放、数值提示共用 |
| 伤害及逐级倍率 | 主动动作资源的 Hits → HitDefinition | CombatResolver |
| 角色属性展示 | `Content/GameData/Stats/Registry.tres` | 人物面板、装备说明 |
| 中英文名称、说明 | `Content/Localization/game_data.csv` | TranslationServer |
| 花果山波次、出生区和墙 | ForestEncounter | GameplayLevel |

`.tres` 的文件名用于定位，运行时靠显式引用与唯一 Id。新文件只放进文件夹还不算登记。资源重命名应检查引用，内容 Id 也不要随意改，因为学习记录、装备实例和任务领取记录会保存 Id。

## 示例：增加20级成长礼包

1. 在 Godot 中复制 `Content/Quests/growth_gift_1.tres`，另存 `growth_gift_2.tres`。对 Rewards 子资源选择“使其唯一”，避免两个礼包共享你准备修改的奖励对象。
2. 改 Id 为 `growth_gift_2`、RequiredLevel 为20，NameKey 为 `QUEST_GROWTH_2_NAME`，DescriptionKey 为 `QUEST_GROWTH_2_DESCRIPTION`。
3. 配 Rewards。每项是 QuestReward：ItemId 写物品目录中的 Id，Count 为正整数。例如 qhsbx ×5；如果要奖励新物品，先登记物品。
4. 编辑 `Content/Quests/Registry.tres` 的 Definitions，**保留原任务**并添加新资源引用。
5. 在翻译表添加下面两行，再让 Godot 导入 CSV：

```csv
QUEST_GROWTH_2_NAME,Growth Gift 2,成长礼包2
QUEST_GROWTH_2_DESCRIPTION,Reach level 20 to claim five enhancement chests.,达到20级即可领取强化石宝箱5个。
```

翻译表表头顺序为 `keys,en,zh_CN`；遵循项目现有表头，不重复键，正文包含逗号时使用 CSV 引号。等级数字写进正文时，改 RequiredLevel 也要同步正文；底下显示的实时等级条件来自服务。

6. 重新打开主地图任务页。列表、领取状态、奖励图标与数量会从目录自动生成，不必复制界面行或新增按钮逻辑。

领取记录目前属于整份存档（ClaimedQuestIds），不是每个角色一份；同存档切换角色不能再次领取同 Id 的礼包。等级条件使用当前角色。奖励只支持已注册的物品，不直接支持经验、货币或每日重置。击杀、收集、日常任务要先设计新的目标/进度规则与保存结构，再接玩法事件，不能只把描述写成“击杀10只”就认为已有计数功能。

### 在代码里调用任务服务

已有地图共用控制器 `Scripts/UI/MainMenu/WorldMap.cs` 完成连接。新增场景需要连接时，使用当前会话的同一个背包和存档：

```csharp
var items = GD.Load<ItemCatalog>("res://Content/Items/ItemCatalog.tres");
var (character, inventory) = GameSessionCharacter.Prepare(items);
var quests = GD.Load<QuestCatalog>("res://Content/Quests/Registry.tres");
var service = new QuestService(quests, character, GameSession.Data!, inventory, items);
var interaction = new QuestInteraction(service, () => GameSession.Save(inventory));
QuestClaimResult result = interaction.ClaimRequested.Send(new("growth_gift_2"));
GD.Print(result.Message);
// interaction 保存在场景字段中，在 _ExitTree 调用 interaction.Dispose()。
```

代码所需命名空间：Godot、Zaomeng.Items、Zaomeng.Save、Zaomeng.Quests。UI 只发送请求、显示结果，不能直接 AddItem 或添加领取 Id。服务先在背包副本试算所有奖励，满包不发部分奖励；提交后保存失败会报告“已发放但保存失败”，不能再次领取。

## 示例：新增武器并挂一个现有效果

最方便的参考是 `Content/Items/ryjgb.tres`（如意金箍棒）。它引用的大品天仙决位于 `Content/GameData/EquipmentSkills/critical_resource_recovery.tres`。

1. 复制装备资源，另存 `Content/Items/my_staff.tres`，改 Id、DisplayName、Icon、DescriptionKey。新增描述键到翻译表。
2. 配 Slot=Weapon、RequiredCharacterId、RequiredLevel、基础属性、SellPrice、Rarity。装备 MaxStack=1；不填 RequiredCharacterId 表示不限制角色。
3. GrantedSkills 添加现有大品天仙决资源。同一装备可以添加多个不同技能。
4. 在 ItemCatalog.tres 的 Definitions 显式添加武器资源。
5. 把新武器加入实际获取来源（掉落、任务奖励、商店等）。**注册不会自动往存档或背包发物品**；目前花果山掉落在 GameplayLevel 的 AwardLoot 中配置。
6. 在背包穿上武器，检查属性和技能列表；卸下后检查效果消失。

Slot 枚举依次为 Weapon、Armor、Accessory、Wing、Title、Costume、MagicWeapon。在 Inspector 选名称即可，不需要记资源文本中的整数。Rarity 决定稀有度和白装批量出售筛选，Quality/QualityColor 负责显示，不能只改文字颜色就认为稀有度改了。批量出售保留已穿戴、有宝石和无售价的装备。

### 改比例，还是增加一种新效果

仅改变回血回蓝比例：复制 `critical_resource_recovery.tres`，将 Effect 子资源“使其唯一”，另设新技能 Id 与翻译键，调 HealthFraction、ManaFraction（0～1），再给武器引用。0.2 表示最大生命/魔法的20%，不是20点。现有效果每个有效暴击命中都触发，没有独立概率或触发冷却。

同一个技能在多件装备上重复授予，当前按 Id 去重，不会叠加；同 Id 不能指向不同定义。需要两种不同效果时使用两个不同 Id。

增加“命中固定回蓝”这类新行为：新建独立 EquipmentSkillEffect 子类，资源只保存参数。例如下面是可参考的接口实现，**示例未注册到游戏**：

```csharp
using System;
using System.Globalization;
using Godot;
namespace Zaomeng.Equipment.Skills;

[GlobalClass]
public partial class FixedManaOnHitEffect : EquipmentSkillEffect
{
    [Export] public float ManaAmount { get; set; } = 3;
    public override void Validate()
    {
        if (!float.IsFinite(ManaAmount) || ManaAmount <= 0)
            throw new InvalidOperationException("回蓝量必须大于零。");
    }
    public override void OnHitDealt(Player owner, CharacterActor target, HitResult hit)
    {
        if (hit.Damage > 0 && !owner.IsDead) owner.RestoreMana(ManaAmount);
    }
    public override string FormatDescription(string template) =>
        string.Format(CultureInfo.CurrentCulture, template, ManaAmount);
}
```

对应技能资源的 Effect 引用该效果，DescriptionKey 的正文可写“有效命中后恢复 {0} 点魔法”。装备只引用技能资源；描述和参数由技能自身提供，背包和战斗共用同一来源。最后登记武器并运行 EquipmentSkillsSmokeTest。不要在 Player 或 CombatResolver 里加 `if (weapon.Id == ...)`。

当前装备技能支持结算前 ModifyOutgoingDamage 和有效命中后 OnHitDealt，子类只覆盖需要的时机。持续Buff、按键主动装备技能、技能独立等级、概率、内置触发冷却尚无通用实现；要加新事件先设计调用位置和运行状态的归属。计时状态不能放在共享 EquipmentSkillEffect Resource 中。

技能专属增伤参考 `Content/GameData/EquipmentSkills/earth_fury.tres`：Effect 使用 `SkillDamageBonusEffect`，TargetSkill 引用目标动作资源，BonusFraction 填 0.5 表示提高50%，再加入装备 GrantedSkills。这类规则不用增加源码。新规则可独立继承 EquipmentSkillEffect 并覆盖 ModifyOutgoingDamage(owner, target, sourceSkill, damage)，返回新伤害；来源通过资源引用判断，普攻 sourceSkill 为空。近战与延迟效果已传递来源，禁止读取玩家当前动画猜来源或修改共享 HitDefinition。地煞怒火作用于烈焰风暴每个命中段，卸下立即失效。

## 增加一个角色主动技能

角色主动技能和装备授予技能是两条不同通路。想让玩家“学习后绑定按键”，要登记 SkillEntry；只想“穿上武器触发”，用 GrantedSkills。

1. 给角色场景的 AnimationPlayer 添加动作，例如 my_skill；先做好动画和碰撞窗口。SkillCatalog 验证会检查动作名是否存在。
2. 在 `Content/Skills/Growth/<角色>` 建 SkillGrowth：InitialLearningCost、LearningCostPerLevel、InitialManaCost、ManaLinearGrowth、ManaQuadraticGrowth。
3. 建 SkillDefinition 动作资源（参考 Wukong/slz.tres），填写 Id、Animation、FramesPerSecond、CooldownSeconds，显式引用 Growth。
4. 配 Hits → HitEvent 的 StartFrame/EndFrame 与 HitDefinition（基础攻击倍率、逐级倍率、类型、击退），按实际动画帧和FPS核对时机。不是所有技能都一定要有直接命中窗口，弹体/治疗可由独立行为负责。
5. 在该角色 Catalog.tres 的 Skills 添加 SkillEntry：Id 必须与动作 Id 一致，DisplayName、Description、Icon、MaximumLevel、Action 引用动作资源。
6. 重新进入游戏验证。学习面板、按键设置、HUD 会读取目录，不改 UI 的技能 Id 分支。

需弹体、飞行、持续特效等特殊逻辑时，先复用 `Content/Skills/Behaviors` 中的已有场景；不适用再建 SkillBehavior 子类和行为场景，动作通过 BehaviorScene 引用。ValidateConfiguration 检查参数和依赖，OnBegin/OnTick/OnStop 负责本次施放；停止、受击、死亡、重置时要恢复修改过的重力/无敌等临时状态。DescribeValues(level) 给数值提示提供当前等级的额外数值，正文不硬写一整张等级表。

当前已学等级写在角色 SkillLevels 中，生效等级由已学等级和装备 SkillLevelBonus 得出，并限制到 MaximumLevel。学习扣费和蓝耗由 Growth 算，伤害成长由 HitDefinition 算，技能面板的数值提示也读它们。改变资源后重新进入场景测试，避免把静态目录缓存当热更新。

### 在运行时学习、装配与施放

```csharp
var learning = new SkillLearningService(character, GameSession.Data!.Wallet);
if (learning.TryLearn("my_skill", out string message))
{
    // slot 为0～4。先设置按键，再把已学主动技能放入该槽。
    if (learning.TrySetKey(0, Key.Y, out message) &&
        learning.TryEquip(0, "my_skill", out message))
    {
        learning.Apply(player);
        GameSession.Save(inventory);
    }
}
GD.Print(message);
// 关卡正常输入会施放；需要程序触发时可调用：
bool cast = player.TryUseSkill(player.GetEquippedSkill(0));
```

增加 `using Zaomeng.Skills;`，character、inventory 使用当前会话实例。TryUseSkill 返回失败表示冷却、蓝耗、角色状态等条件不满足，不能为了强行播放动画绕过这些检查。五个主动槽默认 Y/U/I/O/L，角色目录 ReservedKeys 禁止占用特殊动作键。通关光圈的 W 在范围内优先处理，成功后关闭角色输入。

### 增加被动技能

参考 `Content/Skills/Common/yh.tres`：SkillEntry 的 Action 留空，填写 PassiveBonuses（每项 PassiveStat + Values）与 Growth，并加入角色目录。Values 必须刚好覆盖 MaximumLevel，例如6级必须有6项，不是给旧值再不断累加。当前支持暴击、回血、回蓝、吸血、极速；新属性需要同步被动枚举、计算器与属性展示注册。共享被动资源可以被多个角色目录引用，各角色学习记录仍独立。被动不能放进主动槽。

## 增加角色、属性和装备数值

新角色参考 Tangseng/Catalog.tres：配置 CharacterId、ActorScene、Portrait、SelectionAnimation、ReservedKeys、Skills，再加入 Skills/Registry.tres。关卡按目录装配角色，角色基础成长仍在 CharacterProgression 中；仅登记目录不意味着已有这个角色的基础成长、所有技能、装备外观和剧情。

已有属性加到新装备上，直接配 EquipmentDefinition 的对应 Bonus，例如 HasteBonus。极速公式为 `基础冷却 / (1 + max(0, 极速)/100)`，与动作速度无关。属性名称/说明/格式在 Stats/Registry.tres，翻译在CSV。真正新增一种数值属性，须同步 CharacterStats、属性汇总和使用它的玩法逻辑，再添加展示资源；仅增加展示条目不会凭空产生新战斗机制。

## 检查与调试

先 `dotnet build`，然后用 Godot Mono 运行独立测试场景。测试使用临时数据，优先运行与你改动相关的场景：

| 修改范围 | 测试 |
| --- | --- |
| 任务、白装出售、法宝页、成长展示 | Tests/ContentSystemsSmokeTest.tscn |
| 装备授予技能、暴击效果、翻译说明 | Tests/EquipmentSkillsSmokeTest.tscn |
| 主动/被动注册、改键、唐僧施放 | Tests/SkillCatalogSmokeTest.tscn |
| 实例、穿戴、宝石、物品使用 | Tests/EquipmentInstanceSmokeTest.tscn、EquipmentArchitectureSmokeTest.tscn、ItemActionsSmokeTest.tscn |
| 地形、技能、HUD、4波Boss、W出口 | Tests/GameplayUpgradeSmokeTest.tscn |
| 死亡、结算、重试、空气墙 | Tests/LevelSettlementSmokeTest.tscn |

命令例：`Godot控制台程序 --headless --path . res://Tests/ContentSystemsSmokeTest.tscn`。实际画面检查用非 headless 模式；GameplayUpgradeSmokeTest 可附 `-- --capture-gameplay`，截图保存到 `.godot/gameplay-checks`。不要把 `.godot`、bin/obj 或Python缓存作为内容资源提交。

报“未注册”：检查对应 Registry/Catalog 的引用；报缺动画：核对目录 ActorScene 的动作名；任务领取按钮灰色：检查当前角色等级、ClaimedQuestIds、Rewards的物品Id；装备技能没触发：确认实际穿戴、有效正伤害、效果条件，不要只看背包里是否拥有。
